# Feature Specification: 온라인 대전

## Overview

타이틀에서 대전 방식(컴퓨터, 둘이서, 온라인)을 고른다.
온라인 대전은 로그인(구글, 개발 중에는 stub) 후 서버에서 상대를 찾아 같은 판을 겨루고 승패를 계정에 기록한다.
타이틀의 뒤에서는 캐릭터 둘이 가볍게 싸운다.

## User Scenarios & Testing (mandatory)

### User Story 1: 대전 방식을 고른다

- As: 플레이어는
- I: 타이틀에서 대전 방식을 마우스나 화면 터치로 눌러 정할 수 있다
- So: 컴퓨터와, 같은 컴퓨터에서 둘이서, 온라인으로 겨루기 위해

#### Acceptance Scenarios

Scenario 1: **올린 버튼 표시**

- Given: 타이틀 화면일 때
- When: 마우스를 메뉴의 한 버튼 위로 올리면
- Then: 그 버튼이 강조되고, 버튼 밖으로 벗어나면 강조가 사라진다

Scenario 2: **컴퓨터 대전**

- Given: 타이틀이 나온 지 20프레임이 지났을 때
- When: 「혼자서 컴퓨터와」 버튼을 누르면
- Then: 컴퓨터와의 대전이 시작된다

Scenario 3: **둘이서 대전**

- Given: 타이틀이 나온 지 20프레임이 지났을 때
- When: 「같은 컴퓨터에서 둘이서」 버튼을 누르면
- Then: 한 키보드로 둘이서 하는 대전이 시작된다

Scenario 4: **손가락 모양 커서**

- Given: 타이틀 화면일 때
- When: 마우스가 메뉴의 버튼 위에 있으면
- Then: 커서가 손가락(pointer) 모양이고, 버튼 밖이거나 타이틀이 아니면 기본 모양이다

Scenario 5: **메뉴 밖과 키보드**

- Given: 타이틀 화면일 때
- When: 메뉴 밖을 누르거나 키보드의 방향과 버튼을 누르면
- Then: 대전이 시작되지 않는다

### User Story 2: 로그인하고 상대를 찾는다

- As: 플레이어는
- I: 구글로 로그인하고 서버에서 상대를 찾을 수 있다
- So: 다른 사람과 겨루기 위해

#### Acceptance Scenarios

Scenario 1: **로그인 후 대기**

- Given: 온라인 대전을 골랐을 때
- When: 구글 로그인에 성공하면
- Then: 서버에 접속해 이름과 승패를 받고 대기열에 들어가며 타이틀에 「상대를 찾는 중」이 보인다

Scenario 2: **취소**

- Given: 로그인 중이거나 상대를 찾는 중일 때
- When: 화면을 누르면
- Then: 연결을 닫고 처음 상태로 돌아간다

Scenario 3: **로그인 실패**

- Given: 로그인 창을 닫거나 서버가 오류를 알릴 때
- When: 실패하면
- Then: 이유를 타이틀에 보이고 멈춘다. 서버가 오류를 알린 뒤에는 다시 로그인한다

Scenario 4: **stub 로그인**

- Given: 개발 서버에서 구글 클라이언트 아이디가 설정되지 않았을 때
- When: 온라인 대전을 고르면
- Then: 구글 창 없이 임의의 이름(선수와 번호)으로 로그인해 서버에 접속한다. 서버가 stub을 허용하지 않으면 오류를 보인다

Scenario 5: **설정이 없음**

- Given: 서버 주소나 클라이언트 아이디가 설정되지 않았을 때
- When: 온라인 대전을 고르면
- Then: 「온라인 대전 설정이 없습니다」를 보인다

Scenario 6: **스크립트를 불러오지 못한 뒤 다시 시도**

- Given: 구글 로그인 스크립트를 불러오지 못했을 때
- When: 네트워크가 돌아온 뒤 온라인 대전을 다시 고르면
- Then: 실패를 기억하지 않고 스크립트를 다시 불러온다

Scenario 7: **만료된 토큰**

- Given: 한 번 로그인한 구글 ID 토큰이 만료되었거나 60초 안에 만료될 때
- When: 온라인 대전을 다시 고르면
- Then: 그 토큰으로 접속하지 않고 로그인부터 다시 한다

Scenario 8: **로그인 창**

- Given: 구글 로그인이 필요할 때
- When: 로그인 창이 열리면
- Then: 어둡게 흐린 배경 가운데 초록 카드에 제목 「온라인 대전」, 안내 문구, 구글 로그인 버튼, 취소 버튼이 위에서 아래로 보인다

### User Story 3: 상대와 같은 판을 겨룬다

- As: 짝지어진 플레이어는
- I: 상대와 같은 화면, 같은 프레임으로 겨룰 수 있다
- So: 공정하게 대전하기 위해

#### Acceptance Scenarios

Scenario 1: **시작**

- Given: 서버가 상대를 정해 자리를 알려 주면
- When: 새 판이 시작되면
- Then: 내 입력은 알려 준 자리(1P 또는 2P)에 들어간다

Scenario 2: **입력이 모여야 진행**

- Given: 상대 입력이 아직 도착하지 않았을 때
- When: 프레임을 진행하려 하면
- Then: 진행하지 않고 글자는 띄우지 않으며, 도착하면 이어서 진행한다

Scenario 3: **일시정지 없음**

- Given: 온라인 대전 중일 때
- When: 일시정지를 누르거나 창을 벗어나면
- Then: 멈추지 않는다

Scenario 4: **멈춘 시간을 따라잡음**

- Given: 상대 입력이 늦어 프레임을 진행하지 못한 틱이 있을 때
- When: 입력이 도착하면
- Then: 진행하지 못한 프레임의 시간을 돌려받아 한 틱에 최대 4프레임까지 따라잡는다. 돌려받아 쌓아 두는 시간은 100밀리초 분량까지다

Scenario 5: **핑 표시**

- Given: 온라인 대전 중일 때
- When: 서버가 ping에 pong으로 답하면
- Then: 화면 오른쪽 아래에 서버와의 왕복 시간을 `Ping 38ms`처럼 보인다. 60밀리초 이하는 초록, 120밀리초 이하는 금색, 그보다 크면 빨강이다. 아직 재지 못했거나 대전 중이 아니면 보이지 않는다

### User Story 4: 승패가 기록된다

- As: 플레이어는
- I: 판이 끝나면 내 승패가 기록되기를 바란다
- So: 내 기록을 쌓기 위해

#### Acceptance Scenarios

Scenario 1: **결과 보고와 기록**

- Given: 한 판(3판 2선승)이 끝났을 때
- When: 두 사람이 보고한 이긴 쪽이 같으면
- Then: 서버가 승패를 한 번 기록하고 「내 기록 N승 M패」를 보인다

Scenario 2: **어긋난 보고**

- Given: 두 사람의 보고가 다를 때
- When: 서버가 비교하면
- Then: 기록하지 않고 오류를 알린다

Scenario 3: **상대가 나감**

- Given: 판 도중일 때
- When: 상대가 나가거나 연결이 끊기면
- Then: 남은 사람의 승으로 기록하고, 판을 끝내고 타이틀로 돌아간다. 기록이 오기 전에는 「상대가 나갔습니다」가, 기록이 오면 「내 기록 N승 M패」가 보인다

Scenario 4: **끝난 뒤의 정리**

- Given: 승패가 이미 기록되었을 때
- When: 상대가 나가면
- Then: 알리지 않고 내 기록을 그대로 보인다

Scenario 5: **나간 뒤 다시 시작**

- Given: 상대가 나가 타이틀로 돌아왔을 때
- When: 온라인 대전을 다시 고르면
- Then: 남아 있던 연결을 닫고 새로 접속하므로 「이미 접속 중인 계정입니다」로 거절되지 않는다

### User Story 5: 타이틀 뒤에서 캐릭터가 싸운다

- As: 타이틀을 보는 플레이어는
- I: 뒤에서 캐릭터 둘이 가볍게 싸우는 모습을 볼 수 있다
- So: 타이틀이 정지 화면이 아니라 살아 있는 화면으로 보이기 위해

#### Acceptance Scenarios

Scenario 1: **싸움이 이어진다**

- Given: 타이틀이 나와 있을 때
- When: 시간이 지나면
- Then: 두 캐릭터가 서로 다가가 공격하고, 체력이 낮아지면 채워져 K.O. 없이 싸움이 이어진다

Scenario 2: **소리가 없다**

- Given: 타이틀 뒤의 대전에서 공격이 맞을 때
- When: 맞는 불꽃과 먼지가 나와도
- Then: 소리는 나지 않는다

Scenario 3: **판이 끝나면 새 판**

- Given: 타이틀 뒤의 대전에서 한 판이 끝났을 때
- When: 시간이 지나면
- Then: 새 판이 시작되어 싸움이 이어진다

Scenario 4: **대전을 시작하면 멈춘다**

- Given: 타이틀 뒤의 대전이 진행 중일 때
- When: 실제 대전이 시작되면
- Then: 배경 대전은 멈추고 실제 대전의 캐릭터가 나온다

## Functional Requirements (mandatory)

- FR-1: MUST 타이틀에 「혼자서 컴퓨터와」, 「같은 컴퓨터에서 둘이서」, 「온라인 대전」 버튼 세 개를 가로로 나란히 보이고, 글자는 줄을 바꿔 쓴다. 마우스나 화면 터치로 눌러 정하고, 마우스를 올린 버튼은 강조한다. 키보드로는 고르지 않는다.
- FR-2: MUST 컴퓨터 대전과 둘이서 대전은 선택하기 전과 같게 동작한다.
- FR-3: MUST 온라인 대전은 로그인 후에만 시작한다. 구글 로그인을 쓰고, 개발 중에는 임시 로그인으로 대신할 수 있다. 서버 주소와 구글 클라이언트 아이디는 빌드 설정으로 받으며, 설정이 없으면 없다고 알린다.
- FR-4: MUST 서버에 접속해 대기열에 들어가고 취소할 수 있다.
- FR-5: MUST 두 사람이 모이면 서버가 정한 자리(1P 또는 2P)로 같은 판을 시작한다.
- FR-6: MUST 두 사람의 입력이 모인 프레임만 진행한다. 내 입력은 조금 뒤(6프레임 뒤)의 프레임에 반영해 상대 입력이 도착할 시간을 번다.
- FR-7: MUST 판이 끝나면 이긴 쪽을 서버에 한 번 알리고 기록된 내 승패를 보인다. 승패는 두 사람의 보고가 같을 때만 한 판에 한 번 기록한다.
- FR-8: MUST 상대가 나가거나 연결이 끊기면 판을 끝내고 타이틀로 돌아간다. 이유(「상대가 나갔습니다」)를 보이고, 승패가 기록되면 내 기록으로 바뀐다.
- FR-9: MUST 온라인 대전 중에는 일시정지와 창 이탈 일시정지를 쓰지 않는다.
- FR-10: MUST 같은 계정은 한 번에 하나만 접속할 수 있다. 상대에게 보이는 이름은 길이와 문자를 거른다. 로그인 검증용 구글 공개 키를 일시적으로 가져오지 못해도 이미 받은 키로 로그인할 수 있다.
- FR-11: MUST 타이틀이 나와 있는 동안 뒤에서 캐릭터 둘이 소리 없이 가볍게 싸우고, K.O.가 나지 않으며, 판이 끝나면 새 판이 이어진다.
- FR-12: MUST 이 게임이 만드는 모든 버튼(타이틀 버튼, 공격 버튼, 일시정지, 로그인 창의 취소)은 마우스를 올리면 손가락(pointer) 모양 커서다. 구글이 그리는 로그인 버튼은 구글의 화면이라 제외한다.
- FR-13: MUST 온라인 대전 중에는 서버까지의 왕복 시간의 평균을 화면 오른쪽 아래에 `Ping Nms`로 보인다. 새 판이 시작되면 이전 값을 지운다.
- FR-14: MUST 상대 입력을 기다리느라 멈춘 시간 때문에 게임이 느려지지 않는다. 입력이 도착하면 멈춘 만큼 따라잡고, 기다리는 동안 안내 글자는 띄우지 않는다.
- FR-15: MUST 온라인 대전을 다시 시작할 때 이전 판의 연결이 남아 있어도 새로 접속할 수 있다.
- FR-16: MUST 구글 로그인 스크립트를 불러오지 못해도 다시 시도하면 불러오고, 로그인한 토큰이 만료되었거나 곧 만료되면 다시 로그인한다.
- FR-17: MUST 구글 로그인 창은 어둡게 흐린 배경 가운데에 초록 카드를 놓고, 카드에 제목 「온라인 대전」, 안내 「구글 계정으로 로그인해 주세요」, 구글이 그리는 로그인 버튼, 취소 버튼을 위에서 아래로 보인다.

## Constraints (mandatory)

- CON-1: MUST 엔진의 규칙은 바꾸지 않는다.
- CON-2: MUST 이메일을 저장하지 않는다.
- CON-3: MUST 배포하는 서버는 HTTPS 뒤에서 `wss`로 노출하고 임시 로그인을 켜지 않는다.
- CON-4: MUST 첫 페이지 용량 기준(4kB), 품질 점수 95 이상, 커버리지(줄·분기 100퍼센트)를 클라이언트와 서버 모두 지킨다.

## Success Criteria (mandatory)

- SC-1: 단위 테스트가 위 시나리오를 확인하고 클라이언트 커버리지는 줄과 분기가 모두 100퍼센트다.
- SC-2: 서버 테스트가 로그인 검증, 매칭, 입력 중계, 기록 일치와 불일치, 도중 이탈, 중복 접속, 저장 복원, 연결 확인, 실행 진입을 확인하고 경쟁 조건 검사를 반복해서 통과하며 문장과 분기 커버리지가 100퍼센트다.
- SC-3: 두 브라우저가 서로를 찾아 같은 판을 끝까지 진행하고 승패가 한 번씩만 기록된다.
- SC-4: 로그인하지 않고는 온라인 대전을 시작할 수 없다.
- SC-5: 컴퓨터 대전과 둘이서 대전의 기존 테스트가 그대로 통과한다.
- SC-6: 서버 테스트가 ping에 같은 시각의 pong이 오는지 확인하고, 클라이언트 테스트가 핑 측정과 표시, 멈춘 시간의 따라잡기, 나간 뒤 다시 시작을 확인한다.
- SC-7: 서버 테스트가 이름 정리와 공개 키 장애 때 받아 둔 키 사용을 확인하고, 클라이언트 테스트가 스크립트 재시도와 토큰 만료 판정을 확인한다.
