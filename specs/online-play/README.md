# 온라인 대전

## Background

숲속대전은 컴퓨터와 겨루거나 한 키보드로 둘이서 겨루는 게임이었다.
인터넷으로 다른 사람과 겨룰 수 있게 타이틀에서 대전 방식을 고르고, 온라인 대전은 구글 로그인 후 서버에서 상대를 찾아 겨루며 승패를 기록한다.

## Goal

타이틀에서 「혼자서 컴퓨터와」, 「같은 컴퓨터에서 둘이서」, 「온라인 대전」 중 하나를 고른다.
온라인 대전은 로그인한 사람만 하고, 서버가 짝지어 준 상대와 같은 판을 겨루며, 판이 끝나면 승패가 계정에 기록된다.

## How it works

### 타이틀 메뉴

- 마우스로 누르고, 모바일에서는 화면을 눌러 고른다. 키보드로는 고르지 않는다. 마우스와 터치가 같은 포인터 입력이므로 컴퓨터와 모바일이 같은 방식이다.
- 선택지는 가로로 나란히 놓인 정사각형에 가까운 버튼 세 개이고 글자는 줄을 바꿔 두 줄로 쓴다. 마우스를 올린 버튼은 강조되고 커서는 손가락(pointer) 모양이 된다. 화면의 다른 버튼(공격 버튼, 일시정지, 로그인 창의 취소)도 마우스를 올리면 손가락 모양이다.
- 타이틀의 뒤에서는 캐릭터 둘이 가볍게 싸운다. 별도의 연습용 엔진이 컴퓨터끼리 가장 쉬운 난이도로 싸우고, 체력이 낮아지면 채워서 K.O.가 나지 않으며, 소리는 내지 않는다. 타이틀이 나와 있는 동안에만 진행한다.
- 컴퓨터 대전과 둘이서 대전은 온라인 대전을 더하기 전과 같게 동작한다.
- 타이틀이 나온 지 20프레임이 지나기 전에 누른 것은 무시한다.

### 온라인 대전의 흐름

1. 온라인 대전을 고르면 로그인한다. 구글 클라이언트 아이디가 있으면 구글 로그인 창(제목 「온라인 대전」, 안내 문구, 구글 로그인 버튼, 취소 버튼이 든 초록 카드)이 열리고, 없으면 개발 서버에서만 stub 로그인(페이지마다 임의의 아이디와 이름)으로 바로 넘어간다. 이미 로그인했으면 건너뛴다.
2. 서버에 접속해 로그인 정보를 보내면 서버가 이름과 승패를 알려 주고, 대기열에 들어간다. 타이틀에 「상대를 찾는 중」이 보이고 화면을 누르면 취소한다.
3. 두 사람이 모이면 서버가 자리(1P 또는 2P)를 정해 주고 같은 판이 시작된다.
4. 판이 끝나면 이긴 쪽을 서버에 알린다. 두 사람의 보고가 같을 때 승패가 기록되고 내 기록이 보인다.
5. 결과 화면에서 버튼을 눌러 타이틀로 돌아오면 서버와의 연결을 닫는다. 상대가 나가 판이 끝났을 때는 연결이 남아 있으므로, 온라인 대전을 다시 고르면 남은 연결을 먼저 닫고 새로 접속한다.

### 같은 판을 진행하는 방법

- 두 브라우저가 같은 엔진을 각자 돌린다. 서버는 게임을 계산하지 않고 입력을 상대에게 전달한다.
- 프레임마다 두 사람의 입력이 모여야 그 프레임을 진행한다(입력 지연 락스텝). 내 입력은 지금 프레임이 아니라 6프레임 뒤의 번호로 보내 상대 입력이 도착할 시간을 번다.
- 상대 입력이 늦으면 글자를 띄우지 않고 진행만 멈춘다. 멈춘 프레임의 시간은 돌려받아, 입력이 도착하면 한 틱에 최대 4프레임까지 따라잡는다(돌려받아 쌓는 시간은 100밀리초까지).
- 온라인 대전 중에는 일시정지가 없다.
- 대전 중에는 화면 오른쪽 아래에 서버와의 왕복 시간을 `Ping 38ms`처럼 보인다. 1초마다 서버에 ping을 보내 pong이 돌아오는 시간을 재고, 최근 값에 30퍼센트를 반영한 평균을 쓴다. 60밀리초 이하는 초록, 120밀리초 이하는 금색, 그보다 크면 빨강이다.

### 서버

- 계정 관리(구글 ID 토큰 검증), 승패 기록, 매칭, 입력 전달을 하는 Go 서버가 `server/`에 있다. 실행과 프로토콜은 `server/README.md`에 있다.
- 서버 주소와 구글 클라이언트 아이디는 빌드 환경 값(`VITE_SERVER_URL`, `VITE_GOOGLE_CLIENT_ID`)으로 받는다. 개발 서버에서는 값이 없으면 로컬 서버(`ws://localhost:58970/ws`)와 stub 로그인을 쓰고, 빌드한 결과물은 값이 없으면 온라인 대전을 고를 때 설정이 없다고 알린다.
- stub 로그인은 서버가 `AUTH_STUB`을 켰을 때만 통한다. 켜지 않으면 구글 토큰만 받는다.
- 서버 주소(`VITE_SERVER_URL`)를 주면 개발 서버와 빌드가 그 출처를 페이지의 보안 정책(CSP) 연결 허용에 더한다. 서버는 게임과 포트가 달라 같은 출처가 아니기 때문이다. 서버가 허용하는 웹소켓 출처(`ALLOWED_ORIGIN`)는 게임을 여는 주소와 같아야 한다.
- 로컬 서버는 전용 스크립트(`server/dev-server.sh start, stop, restart, status`)로만 켜고 끈다. 서버 포트를 쓰는 프로세스 중 실행 폴더가 `server/`인 것만 끄므로 다른 서버를 건드리지 않는다. 스크립트는 Go를 `go.mod`의 `go` 줄 버전으로 mise를 거쳐 실행한다.
- 서버의 배포(Docker 컨테이너, nginx, Cloudflare)는 별도 기능 `../server-infra/README.md`에 있다.
