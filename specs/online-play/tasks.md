# Tasks: 온라인 대전

## Goal

타이틀에서 대전 방식을 고르고, 온라인 대전은 구글 로그인 후 서버에서 상대를 찾아 겨루며 승패를 기록한다.

## Current Phase

✅ Phase 4: Testing

## Phases

### Phase 1: Requirements & Discovery ✅

- [x] 요구사항 정의(세 가지 대전 방식, 구글 로그인, 매칭, 승패 기록)
- [x] 스펙 문서 작성 (spec.md)

### Phase 2: Planning & Structure ✅

- [x] 동기화 방식 정하기(입력 지연 락스텝, 서버는 입력 전달)
- [x] 프로토콜과 서버 구성 정하기 (plan.md)
- [x] 메뉴, 온라인 흐름, 락스텝, 서버 통신의 역할 나누기

### Phase 3: Implementation ✅

- [x] Step 1: Go 서버(인증, 매칭, 중계, 기록)
- [x] Step 2: 입력 부호화, 락스텝, 서버 메시지
- [x] Step 3: 온라인 흐름, 구글 로그인
- [x] Step 4: 타이틀 메뉴와 게임 연결
- [x] Step 5: 보안 정책과 환경 값
- [x] 정사각형에 가까운 버튼 세 개와 글자 줄바꿈
- [x] 타이틀 뒤의 배경 대전(연습용 엔진)
- [x] stub 로그인(클라이언트와 서버)
- [x] 개발용 서버 전용 켜고 끄기 스크립트(`server/dev-server.sh`)와 켜기, 끄기, 다시 켜기 확인
- [x] 모든 버튼 위의 커서를 손가락 모양으로(캔버스 버튼, 조작 버튼, 일시정지, 로그인 창 취소)
- [x] 단계별 타입 검사
- [x] 입력 지연을 6프레임으로 올리고 대기 안내 글자 없애기
- [x] 상대 입력을 기다리느라 진행하지 못한 시간을 돌려받아 따라잡기(`FixedStepLoop`)
- [x] 상대가 나간 뒤 다시 시작할 때 남은 연결 닫기
- [x] 핑 측정(서버 `ping`/`pong`, 클라이언트 `PingMeter`)과 오른쪽 아래 표시

### Phase 4: Testing ✅

- [x] 클라이언트 단위 테스트와 전체 검사 통과(`pnpm run check:full`)
- [x] 서버 테스트와 경쟁 조건 검사 통과(`go test -race`)
- [x] 구글 로그인 결함 수정(이름 정리, 공개 키 장애 대비, 스크립트 불러오기 재시도, 만료된 토큰 다시 쓰지 않기)과 테스트
- [x] 서버(Go) 문장 커버리지 100퍼센트, 분기 커버리지 100퍼센트(`gobco`), 정적 분석(`go vet`, `staticcheck`)과 서식 통과, `pnpm run check`에 점검(`check:server`) 포함
- [x] 타이틀 메뉴 화면 확인(버튼 모양과 뒤에서 싸우는 캐릭터)
- [x] 서버 stub 로그인으로 매칭과 기록까지 이어지는 통합 테스트(`handler_test.go`)
- [x] 로컬 서버(stub 로그인)와 브라우저 두 탭으로 매칭되고 같은 판이 진행되는지 확인(자동 조작 브라우저)
- [x] 구글 로그인 창 모양 개선(초록 카드, 제목, 안내 문구, 취소 버튼)과 화면 확인
- [x] 실제 구글 로그인으로 확인
- [x] 같은 판을 끝까지 진행하고 승패가 한 번씩 기록되는지 확인
- [x] 판 도중 한쪽이 나갔을 때 기록 확인
- [x] 느린 연결에서 입력 지연 값 확인(두 컴퓨터에서 끊김과 핑을 확인하고 6프레임을 유지)
- [x] 상대 봇을 붙여 온라인 대전을 브라우저로 확인(핑 표시, 키를 누르고 있을 때 이동)
- [x] 두 사람이 서로 다른 컴퓨터에서 대전하며 끊김과 핑 확인
