# Feature Specification: 모바일 조작

## Overview

폰 화면에 조이스틱, 공격 버튼 네 개, 일시정지 버튼을 놓고 1P의 키보드 입력으로 옮긴다.
터치 기기에서만 보이며 컴퓨터에서는 나타나지 않는다.
타이틀과 일시정지 화면의 안내 문구는 입력 장치에 맞게 나온다.

## User Scenarios & Testing (mandatory)

### User Story 1: 폰으로 컴퓨터와 대전한다

- As: 폰으로 접속한 플레이어는
- I: 화면의 조이스틱과 버튼으로 1P 캐릭터를 조작할 수 있다
- So: 키보드 없이도 대전하기 위해

#### Acceptance Scenarios

Scenario 1: **버튼 네 개**

- Given: 아무것도 누르지 않았을 때
- When: 약펀치, 약킥, 강펀치, 강킥 버튼을 하나씩 누르면
- Then: 1P 입력의 A, B, C, D가 차례로 켜지고 2P 입력은 변하지 않는다

Scenario 2: **버튼을 뗌**

- Given: 버튼을 누르고 있을 때
- When: 손가락을 떼거나 터치가 취소되면
- Then: 그 버튼은 눌리지 않은 것으로 돌아오고 눌림 표시도 사라진다

Scenario 3: **일시정지**

- Given: 대전 중일 때
- When: 일시정지 버튼을 누르면
- Then: 게임이 멈추고, 다시 누르면 계속된다

### User Story 2: 조이스틱으로 방향과 점프를 낸다

- As: 플레이어는
- I: 조이스틱을 밀어 걷기, 앉기, 점프를 낼 수 있다
- So: 정확한 방향 입력으로 기술을 쓰기 위해

#### Acceptance Scenarios

Scenario 1: **어디에 닿아도 같다**

- Given: 조이스틱의 가운데가 아닌 곳에 손가락을 댔을 때
- When: 그 자리에서 곧게 위로 밀면
- Then: 위만 눌린다

Scenario 2: **대각선**

- Given: 손가락이 닿아 있을 때
- When: 위와 앞쪽으로 비스듬히 밀면
- Then: 위와 앞이 함께 눌린다

Scenario 3: **조금 움직인 것은 무시**

- Given: 손가락이 닿아 있을 때
- When: 끝까지 민 거리의 0.35배보다 적게 움직이면
- Then: 아무 방향도 눌리지 않는다

Scenario 4: **반대로 밀기**

- Given: 끝까지 민 거리보다 훨씬 멀리 밀었을 때
- When: 반대쪽으로 손가락을 되돌리면
- Then: 기준점이 따라와 있어서 짧게 되돌려도 반대 방향이 눌린다

Scenario 5: **손가락을 뗌**

- Given: 방향을 누르고 있을 때
- When: 손가락을 떼거나 터치가 취소되면
- Then: 모든 방향이 놓이고 손잡이가 가운데로 돌아온다

### User Story 3: 컴퓨터에서는 보이지 않는다

- As: 키보드를 쓰는 플레이어는
- I: 화면에 조이스틱이 나타나지 않기를 바란다
- So: 게임 화면이 가려지지 않기 위해

#### Acceptance Scenarios

Scenario 1: **터치 기기에서만 보임**

- Given: 터치 기기가 아닌 컴퓨터 화면일 때
- When: 페이지를 열면
- Then: 화면 조작 요소는 표시되지 않는다

### User Story 4: 두 손가락으로 조작해도 확대되지 않는다

- As: 플레이어는
- I: 한 손으로 조이스틱, 다른 손으로 버튼을 눌러도
- So: 화면이 확대되지 않고 계속 대전하기 위해

#### Acceptance Scenarios

Scenario 1: **확대 동작 차단**

- Given: 페이지가 열려 있을 때
- When: 브라우저가 확대 동작(`gesturestart`)을 시작하면
- Then: 그 기본 동작이 취소된다

Scenario 2: **터치 기본 동작 차단**

- Given: 조작 영역에 손가락을 댔을 때
- When: 터치 시작, 터치 이동, 길게 누르기가 일어나면
- Then: 각각의 기본 동작이 취소된다

### User Story 5: 안내 문구가 입력 장치에 맞는다

- As: 폰으로 하는 플레이어는
- I: 없는 키(Space)를 안내받지 않고 화면에 있는 버튼을 안내받는다
- So: 일시정지와 조작법을 찾기 위해

#### Acceptance Scenarios

Scenario 1: **타이틀 문구**

- Given: 터치 기기로 타이틀 화면을 열었을 때
- When: 화면 아래 문구를 보면
- Then: Space가 아니라 오른쪽 위 일시정지 버튼(⏸)을 안내한다

Scenario 2: **일시정지 화면**

- Given: 터치 기기에서 일시정지했을 때
- When: 일시정지 화면을 보면
- Then: 키보드 그림과 Space 안내가 없고, 일시정지 버튼으로 계속하라는 문구가 나온다

Scenario 3: **키보드 화면은 그대로**

- Given: 터치 기기가 아닌 컴퓨터일 때
- When: 타이틀 화면과 일시정지 화면을 보면
- Then: Space 안내와 1P·2P 키보드 그림이 그대로 나온다

## Functional Requirements (mandatory)

- FR-1: MUST 모바일의 입력은 언제나 1P의 입력이며, 1P의 방향키와 I K O L을 누르고 뗀 것과 같다.
- FR-2: MUST 화면에 조이스틱 하나, 공격 버튼 네 개(위 줄 약펀치·강펀치, 아래 줄 약킥·강킥), 일시정지 버튼 하나를 둔다.
- FR-3: MUST 이 요소는 터치 기기(`pointer: coarse`)에서만 보인다.
- FR-4: MUST 조이스틱은 손가락이 처음 닿은 곳을 가운데로 삼아 움직인 만큼을 기울기로 읽고, 조이스틱 너비의 0.4배를 밀면 끝까지 민 것이다.
- FR-5: MUST 기울기가 끝까지의 0.35배보다 작으면 아무 방향도 누르지 않은 것으로 본다.
- FR-6: MUST 방향은 여덟 방향으로 나눈다. 작은 축의 기울기가 큰 축의 0.414배보다 작으면 그 축은 누르지 않는다.
- FR-7: MUST 끝까지 민 거리를 넘으면 기준점이 손가락 쪽으로 따라온다.
- FR-8: MUST 손가락을 떼거나 터치가 취소되면 모든 방향을 놓고 손잡이가 가운데로 돌아온다.
- FR-9: MUST 일시정지 버튼은 Space와 같이 일시정지를 켜고 끈다.
- FR-10: MUST 확대 동작(`gesturestart`)과 조작 영역의 터치 시작·이동·길게 누르기 기본 동작을 막고, 뷰포트에서 확대를 끈다.
- FR-11: MUST 타이틀 문구와 일시정지 화면은 입력 장치에 맞는 안내로 그리고, 터치 기기에서는 Space 대신 일시정지 버튼을 안내하며 키보드 그림을 그리지 않는다.
- FR-12: MUST 입력 장치는 시작할 때 `pointer: coarse`로 한 번 정한다.

## Constraints (mandatory)

- CON-1: MUST 엔진과 컴퓨터 상대의 코드는 바꾸지 않는다.
- CON-2: MUST 모바일 입력을 읽는 코드(`src/input/touch/`)는 엔진의 상태를 바꾸지 않고 키보드 입력만 만든다.
- CON-3: MUST 일시정지를 켜고 끄는 코드는 `Game.togglePause` 한 곳에 둔다.
- CON-4: SHOULD 입력 장치마다 다른 안내 문구는 `GUIDES` 표에만 둔다.

## Success Criteria (mandatory)

- SC-1: 단위 테스트가 위 시나리오를 확인하고 커버리지는 줄과 분기가 모두 100퍼센트다.
- SC-2: 곧게 위로 민 입력은 위만 누르고, 비스듬히 민 입력은 두 방향을 누른다.
- SC-3: 두 손가락 조작에서 브라우저의 확대 동작이 취소된다.
- SC-4: 터치 기기의 타이틀과 일시정지 화면에 Space 안내가 없다.
- SC-5: 실제 폰에서 점프, 앉기, 걷기와 기술 입력이 잘 나가고 화면이 확대되지 않는다.
