# Findings & Decisions

> **기술적 발견, 중요한 결정이 있을 때마다 이 파일을 즉시 업데이트하세요.**

## Requirements

- 온라인 대전 서버(Go)를 서버의 Docker 컨테이너로 배포한다.
- 앞에는 Cloudflare와 nginx를 둬서 브라우저가 `wss`로 접속한다.
- 배포와 점검을 Ansible 절차로 한다.
- 배포 파일은 정적 분석을 지적 0건으로 통과한다.
- 서버를 여러 대로 늘리는 것, 데이터베이스로 옮기는 것, 자동 배포(CI)는 이 기능의 범위가 아니다.

## Research Findings

### 코드베이스 구조

- `server/main.go`가 읽는 환경 변수: `PORT`(기본 58970), `GOOGLE_CLIENT_ID`, `ALLOWED_ORIGIN`, `DATA_FILE`, `AUTH_STUB`. 구글 클라이언트 아이디가 없고 `AUTH_STUB`도 꺼져 있으면 시작하지 않는다.
- `server/store.go`는 임시 파일에 쓴 뒤 이름을 바꿔 저장한다(`os.WriteFile`, `os.Rename`). 그래서 파일 하나가 아니라 같은 폴더에 쓸 수 있어야 한다.
- 서버는 `/healthz`(`ok`)와 `/ws`만 가진다.
- 게임 화면의 보안 정책(CSP)은 `connect-src`에 `wss:`를 이미 열어 두었다(`index.html`, `vercel.json`).

### 기존 패턴

- 점검 스크립트는 `_agent/checks/`에 두고 `pnpm run`으로 부르며, 위반이 있으면 종료 코드 1로 끝낸다.

## Technical Decisions

| Decision | Rationale |
| -------- | --------- |
| 서버를 Vercel이 아니라 서버의 Docker 컨테이너로 배포한다 | Vercel의 함수는 요청마다 잠깐 실행되고 끝나므로, 연결을 붙들고 대기열과 대전 상태를 메모리에 가지는 서버를 올릴 수 없다. 게임 화면(정적)만 Vercel에 둔다. |
| 이미지는 레지스트리 없이 직접 올린다 | 서버가 한 대이고 배포하는 컴퓨터에서 한 번에 올리면 되므로, 레지스트리 계정과 저장소, 인증 설정을 따로 관리하지 않기 위해서다. |
| 컨테이너는 하나만 띄운다 | 서버가 매칭 대기열을 메모리에 가지므로 여러 개로 늘리면 두 사람이 서로 다른 컨테이너에 붙어 매칭되지 않는다. |
| 승패 기록은 파일이 아니라 폴더를 서버의 폴더에 연결한다 | 서버가 같은 폴더에 임시 파일을 쓰고 이름을 바꾸는 방식으로 저장하기 때문이다. |
| 실행 사용자는 root가 아닌 `forestclash`(uid 10001)이고 데이터 폴더의 소유자도 같다 | 컨테이너가 뚫려도 서버의 root 권한을 얻지 못하게 하기 위해서다. |
| 이미지에서 `*.json`을 뺀다 | 승패 기록 파일에는 이름과 승패가 들어 있어 이미지에 들어가면 안 된다(`go.mod`와 `go.sum`은 이름이 달라 들어간다). |
| 컨테이너 포트 58970을 호스트에 그대로 내보내고 바깥의 nginx가 `게임서버:58970`으로 연결한다 | 포트를 바꾸지 않아 nginx와 서버 설정이 단순하다. nginx를 이 저장소가 띄우지 않고 서버에 있는 것을 같이 쓴다. |
| 서버의 환경변수는 `infra/vars.yml`의 `server_env`에 두고 `AUTH_STUB`은 넣지 않는다 | 서버에 환경변수 파일이 필요 없고, 켜면 누구나 아무 이름으로 로그인할 수 있기 때문이다. |
| 컨테이너 실행 단계는 환경변수 값이 로그에 남지 않게 출력을 숨긴다(`no_log`) | 구글 클라이언트 아이디 등이 배포 로그에 남지 않게 하기 위해서다. |
| 배포 파일의 정적 분석 도구는 설치하지 않고 이미지 다이제스트를 고정해 Docker로 실행한다 | 개발 컴퓨터에 도구를 깔지 않고 같은 버전으로 반복해서 같은 결과를 얻기 위해서다. |
| 실행 사용자는 이름이 아니라 번호(`USER 10001:10001`)로 적는다 | hadolint(DL3066)가 이름은 서버가 풀지 못할 수 있다고 지적하고, 번호는 `/data` 폴더의 소유자(uid 10001)와 직접 맞는다. |
| 상태 확인 명령은 `CMD ["sh", "-c", ...]` 형태로 적는다 | hadolint(DL3025)가 JSON 형태를 요구하고, `${PORT}`를 풀려면 셸이 필요하다. |
| Ansible은 모든 모듈을 `ansible.builtin.*`로 적고 파이프에는 `pipefail`을 건다 | ansible-lint production 기준(fqcn, risky-shell-pipe, no-changed-when, command-instead-of-shell)을 지키기 위해서다. |
| 서버를 먼저 배포하고 게임 화면을 나중에 배포한다 | 새 화면이 새 메시지를 보내는데 옛 서버는 오류로 답하고, 화면은 오류를 받으면 대전을 끝내기 때문이다. |
| 컨테이너는 읽기 전용 파일 시스템, 권한 전부 제거, 새 권한 금지, 메모리 256MB, 프로세스 256개로 실행한다 | 서버가 쓰는 곳은 `/data` 하나이고 특별한 권한이 필요 없으므로, 컨테이너가 뚫려도 할 수 있는 일을 줄이고 자원을 다 써 버리는 것을 막기 위해서다. 같은 옵션으로 이미지를 띄워 `/healthz` 응답과 `/data` 쓰기를 확인했다. |
| 기본 이미지(`golang`, `alpine`)는 다이제스트로 고정한다 | 같은 태그가 나중에 다른 이미지를 가리켜도 같은 이미지로 빌드하기 위해서다. |

## Issues Encountered

### 1. 호스트 포트를 어떻게 내보낼 것인가

**문제**:

처음에는 호스트의 `127.0.0.1:18970`으로만 열고 nginx가 컨테이너 이름으로 접근하는 구성이었다.

**원인**:

서버의 nginx는 `게임서버:58970`으로 연결하는데, 초안은 호스트의 `127.0.0.1:18970`만 열고 포트도 서버의 기본값(58970)과 달라 nginx가 연결할 수 없었다.

**해결**:

`server_host_port`를 58970으로 하고 `-p 58970:58970`으로 내보낸다. 이 포트는 호스트의 모든 인터페이스에 열리고 Docker가 연 포트는 `ufw`를 거치지 않으므로, 직접 접속을 막으려면 서버 앞단에서 58970을 nginx에서만 들어오게 제한해야 한다고 `infra/README.md`에 적었다.

**결과**:

`deploy.yml`, `vars.yml.example`, `infra/README.md`가 같은 포트를 가리킨다.

### 2. 처음 만든 배포 파일이 정적 분석에 걸린다

**문제**:

`Dockerfile`이 hadolint에서 2건(DL3066, DL3025), Ansible 절차가 ansible-lint production 기준에서 수십 건(모듈 이름, 파이프, 변경 판정, 긴 줄)의 지적을 받았다.

**원인**:

배포 절차를 쓰면서 전용 정적 분석을 돌리지 않았다.

**해결**:

실행 사용자를 번호로, 상태 확인을 JSON 형태로 바꾸고, Ansible의 모든 모듈을 `ansible.builtin.*`로 적고, 파이프에 `pipefail`을, 명령에 `changed_when`을 더했다. 셸이 필요 없는 곳은 `command`로 바꿨다.

**결과**:

`pnpm run check:infra`가 지적 0건이다. 바꾼 이미지를 다시 빌드해 `healthy`, 입력 중계, 기록 파일 저장을 확인했고 Ansible 문법 검사도 통과했다. 틀린 `Dockerfile` 줄을 임시로 넣어 위반을 잡는 것도 확인했다.

### 3. `go install`로 도구를 깔면 저장소 바깥에 실행 파일이 남는다

**문제**:

서버 점검 도구를 `go install`로 받자 실행 파일이 mise의 Go 설치 폴더에 들어갔다.

**원인**:

`go env GOBIN`이 mise의 Go 설치 폴더의 `bin`을 가리켜서, 환경 값으로 다른 폴더를 주어도 실행 파일이 그 폴더에 쓰였다.

**해결**:

두 파일을 지우고, 설치하지 않고 버전을 고정해 `go run`으로 쓰는 방식으로 바꿨다(`_agent/checks/server_checks.cjs`).

**결과**:

저장소 바깥에 남은 파일이 없다.

## Learnings

### 컨테이너를 켜 봐야 이미지가 맞는지 안다 (2026-10-23)

빌드가 끝나도 실행 사용자, 데이터 폴더 권한, 상태 확인은 컨테이너를 띄우고 대전 입력을 중계해 보고 기록 파일이 써지는지 봐야 확인된다.

### 웹소켓은 HTTP와 같은 포트로 간다 (2026-10-23)

연결은 HTTP 요청으로 시작해 웹소켓으로 전환된다. Cloudflare 뒤에서는 브라우저가 443으로 접속하고, nginx가 `Upgrade` 헤더로 전환을 넘겨야 한다.
