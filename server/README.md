# 숲속대전 온라인 서버

온라인 대전에 필요한 계정, 매칭, 입력 중계, 승패 기록을 맡는 서버다. Go로 만들었다.

두 브라우저가 각자 같은 게임 엔진을 돌리고, 서버는 게임을 계산하지 않고 한 사람의 입력을 상대에게 그대로 전달한다. 엔진이 같은 입력에서 같은 결과를 내므로 두 화면이 같은 판을 본다.

## 실행

로컬에서 구글 없이 시험할 때(stub 로그인)는 전용 스크립트로 켜고 끈다.

```sh
cd server
./dev-server.sh start     # 빌드하고 백그라운드로 실행(로그: .dev-server.log)
./dev-server.sh status
./dev-server.sh restart
./dev-server.sh stop
```

스크립트는 Go를 `go.mod`의 `go` 줄 버전으로 mise를 거쳐 실행한다. 이 서버만 다룬다. 이름으로 프로세스를 찾아 끄지 않고, 서버 포트(58970)를 쓰는 프로세스 중 실행 폴더가 `server/`인 것만 끈다. 포트를 다른 프로세스가 쓰고 있으면 건드리지 않고 알린다.
개발용 설정(stub 로그인 켬, 출처는 게임 개발 서버 주소)이 들어 있으므로 배포에는 쓰지 않는다. 출처를 바꾸려면 `ALLOWED_ORIGIN`을, Go 실행 명령을 바꾸려면 `GO`를 환경 값으로 준다.
게임을 다른 주소(예: 같은 네트워크의 다른 기기가 여는 `http://컴퓨터주소:58969`)로 열 때는 같은 폴더의 `.dev-server.env`에 `ALLOWED_ORIGIN="http://컴퓨터주소:58969"`처럼 적는다. 이 파일은 개인 설정이라 저장소에 올리지 않는다(`.gitignore`).

직접 실행하려면:

```sh
cd server
AUTH_STUB=1 ALLOWED_ORIGIN=http://localhost:58969 go run .
```

서버는 58970 포트에서 받고, 게임 개발 서버(`pnpm run dev`, 58969 포트)가 개발 모드의 기본값으로 이 서버에 접속한다.
`ALLOWED_ORIGIN`은 게임을 여는 주소와 같아야 한다. 같은 네트워크의 폰에서 열 때는 그 주소(예: `http://컴퓨터주소:58969`)로 맞춘다.

구글 로그인을 쓸 때:

```sh
cd server
GOOGLE_CLIENT_ID=<구글 로그인용 클라이언트 아이디> \
ALLOWED_ORIGIN=<게임을 여는 주소> \
go run .
```

점검은 저장소 루트에서 `pnpm run check:server`로 한다. 서식(`gofmt -l`), `go vet`, `staticcheck`이 오류 0건이고, `go test -race`가 모두 통과하며, 문장 커버리지와 분기 커버리지(`gobco`)가 모두 100퍼센트여야 한다. `pnpm run check`가 이 점검을 포함한다.
시험만 빠르게 돌릴 때는 `go test -race ./... -cover`로 한다.

## 환경 변수

| 이름 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| `GOOGLE_CLIENT_ID` | stub이 아니면 예 | | 구글 ID 토큰의 대상(aud)과 비교한다 |
| `AUTH_STUB` | 아니오 | 꺼짐 | `1`이면 `stub:<아이디>:<이름>` 토큰으로 구글 없이 로그인할 수 있다. 누구나 아무 이름으로 들어올 수 있으므로 로컬 개발에서만 켜고 배포할 때는 켜지 않는다. 구글 클라이언트 아이디도 주면 구글 토큰도 함께 받는다 |
| `PORT` | 아니오 | `58970` | 받을 포트 |
| `ALLOWED_ORIGIN` | 아니오 | 비어 있음 | 웹소켓을 열 수 있는 출처(예: `https://game.example`). 비어 있으면 서버와 같은 호스트에서 연 페이지만 허용한다 |
| `DATA_FILE` | 아니오 | `forest-clash-data.json` | 계정과 승패를 저장하는 파일 |

## 주소

| 주소 | 설명 |
|---|---|
| `GET /healthz` | 살아 있는지 확인한다. `ok`를 돌려준다 |
| `GET /ws` | 웹소켓 접속 |

## 프로토콜

웹소켓의 텍스트 메시지이고, 내용은 JSON이며 `type` 필드로 종류를 구분한다. 접속하면 10초 안에 `hello`를 보내야 한다. 메시지는 1KB까지 받는다(`hello`만 8KB).

클라이언트가 서버로 보내는 메시지:

| type | 필드 | 설명 |
|---|---|---|
| `hello` | `token` | 첫 메시지. 구글 ID 토큰(stub이 켜져 있으면 `stub:<아이디>:<이름>`도 된다. 아이디는 영문, 숫자, 밑줄, 붙임표 64자 이하, 이름은 32자까지) |
| `queue` | | 대기열에 들어간다 |
| `cancel` | | 대기를 취소한다 |
| `input` | `frame`, `bits` | 내 입력. `frame`은 0 이상, `bits`는 0\~255. 대전 중일 때 상대에게 전달된다 |
| `result` | `winner` | 판이 끝났을 때 이긴 쪽의 슬롯(0 또는 1) |
| `leave` | | 대전에서 나간다. 접속은 유지된다 |
| `ping` | `sent` | 왕복 시간을 재려고 보낸 시각(숫자). 서버는 해석하지 않고 `pong`에 그대로 돌려준다 |

서버가 클라이언트로 보내는 메시지:

| type | 필드 | 설명 |
|---|---|---|
| `ready` | `name`, `wins`, `losses` | 로그인에 성공했다 |
| `waiting` | | 대기열에 들어갔다 |
| `matched` | `slot`, `opponent`(`name`, `wins`, `losses`) | 상대가 정해졌다. 대기열에 먼저 들어온 사람이 `slot` 0이다 |
| `input` | `frame`, `bits` | 상대의 입력 |
| `recorded` | `wins`, `losses` | 승패가 기록되었다. 내 새 기록이다 |
| `opponentLeft` | | 상대가 나갔다 |
| `pong` | `sent` | `ping`에 대한 답. 받은 `sent`를 그대로 돌려준다 |
| `error` | `reason` | 오류. 로그인 단계의 오류는 접속이 곧 닫힌다 |

입력 비트는 왼쪽, 오른쪽, 위, 아래, A, B, C, D 순서의 8비트다.

## 규칙

- 계정은 구글 토큰의 `sub`로 구분하고 이메일은 저장하지 않는다. 표시 이름은 토큰의 `name`이고, 없으면 `선수`와 번호다.
- 토큰은 RS256 서명, 발급자(`accounts.google.com`), 대상, 만료를 모두 확인한다. 구글의 공개 키는 응답의 `Cache-Control`만큼 캐시하고, 모르는 키 번호가 와도 1분 안에는 다시 가져오지 않는다. 구글에서 새 키를 가져오지 못해도 이미 받은 키가 있으면 그 키로 확인한다.
- 표시 이름은 토큰의 이름(구글 `name`, stub 이름)에서 제어 문자를 빼고 앞뒤 공백을 지운 뒤 32글자까지만 쓴다. 상대 화면에도 보이는 값이라 그대로 믿지 않는다.
- 같은 계정은 한 번에 하나만 접속할 수 있다. 그래서 자기 자신과 매칭되지 않는다.
- 판이 끝나면 두 사람이 `result`로 이긴 쪽을 보고한다. 두 보고가 같을 때만 승패를 기록하고, 한 판에 한 번만 기록한다. 보고가 어긋나면 기록하지 않고 두 사람에게 `error`를 보낸다.
- 판 도중 한쪽이 나가거나 끊기면 남은 사람에게 `opponentLeft`를 보내고, 남은 사람의 승과 떠난 사람의 패로 기록한다. 이미 기록된 판은 다시 기록하지 않는다.
- 연결이 살아 있는지 30초마다 확인하고, 보내는 줄이 가득 찬 느린 연결은 끊는다.

## 저장

계정 전체를 JSON 파일 하나에 저장한다. 임시 파일에 쓴 뒤 이름을 바꾸므로 저장 도중에 멈춰도 파일이 반쯤 쓰인 채로 남지 않는다. 서버는 `Store` 인터페이스만 쓰므로 나중에 데이터베이스로 바꿀 수 있다.

## 배포할 때

- Docker 이미지(`Dockerfile`)로 배포한다. 이미지는 컨테이너 포트 58970으로 받고, 승패 기록은 `/data`(`DATA_FILE=/data/forest-clash-data.json`)에 쓰므로 이 폴더를 서버의 폴더에 연결한다. 절차와 nginx, Cloudflare 설정은 `../infra/README.md`에 있다.
- 배포하는 서버에는 `AUTH_STUB`을 켜지 않는다.
- 새 메시지를 더하는 변경은 서버를 먼저 배포한다. 새 메시지를 모르는 옛 서버는 오류로 답하고 클라이언트는 오류를 받으면 대전을 끝낸다.
- 브라우저의 구글 로그인과 웹소켓은 보안 연결에서 쓰므로 HTTPS 뒤에 두고 `wss`로 노출한다. 서버가 직접 TLS를 처리하지 않으니 앞에 리버스 프록시를 둔다.
- 서버는 프로세스 하나가 모든 대기열과 판을 메모리에 가진다. 서버를 여러 개로 늘리지 않는다.
- 입력을 중계할 뿐이라 클라이언트를 고쳐 부정하게 입력하는 것은 막지 못한다. 승패 기록은 두 사람의 보고가 일치해야 하므로 한 사람이 혼자 거짓 기록을 만들 수는 없다.
