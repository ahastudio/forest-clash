# 코드 품질 점수

코드와 설계의 품질을 0~100점으로 계산한다.
점수는 `_agent/checks/quality_score.cjs`가 계산하고, `pnpm run score`로 실행한다.
테스트 파일(`*.test.ts`)과 `testing/` 폴더는 뺀다.

## 항목

| 항목 | 가중치 | 만점 기준 |
| --- | --- | --- |
| 함수 길이 | 15 | 모든 함수 본문이 문장 5개 이하 |
| 인자 개수 | 5 | 모든 함수의 인자가 3개 이하 |
| 읽히는 인자 | 10 | 불리언 플래그, 같은 타입의 이웃한 숫자·문자열 인자가 없다(좌표처럼 순서가 곧 뜻인 이름은 제외) |
| else if 없음 | 5 | `else if`가 없다 |
| 제어문 중괄호 | 5 | 모든 `if`·`else`·반복문이 중괄호를 쓴다 |
| 조건식 | 10 | `if`·`while`·삼항의 조건이 한 줄이고, `&&`와 `||`를 섞지 않으며, 논리 연산자가 2개 이하이고, 80컬럼 이하 |
| 파일 크기 | 10 | 모든 파일이 300줄 이하 |
| 순환 의존 | 10 | 값으로 가져오는 import에 순환이 없다 |
| 밖에서 쓰이는 export | 10 | export한 것이 다른 파일에서 쓰인다 |
| export 함수의 JSDoc | 10 | export한 함수마다 JSDoc이 있다 |
| 중복 함수 본문 | 10 | 문장 3개 이상인 함수 본문이 같은 것이 없다 |

## 항상 계산한 뒤 대응한다

- 코드나 설계를 고친 뒤, 품질을 말하거나 보고하기 전에 점수를 계산한다. 계산하지 않고 품질이 좋다고 말하지 않는다.
- 총점이 기준(프로젝트의 `score` 스크립트의 `--min`) 아래이거나 이전보다 내려갔으면 보고하지 않고 먼저 고친다. 가장 낮은 항목부터 위반 위치(`--verbose`)를 후보로 뽑아 고친다. 고치지 못한 것은 `core-principles.md`의 「못 고친 것」 형식으로 사유를 적는다.
- 보고에는 총점과 항목별 점수를 명령 출력 그대로 적는다.
- 점수는 이름, 책임 분리, 응집을 판단하지 못한다. 만점이어도 사람이 읽어 판단하는 일은 남는다.

## 쓰레기 코드는 금지한다

- 쓰이지 않는 변수, 함수, export, 파일, 의존성.
- 주석 처리된 코드와 디버그 잔재(`console.log`, `debugger`, 쓰지 않는 TODO).
- 지표만 맞추려고 만든 의미 없는 래퍼, 이름, 주석. 점수를 올리려고 읽기 어렵게 쪼개거나 설명 없는 JSDoc을 채우지 않는다.
- 같은 본문의 중복.
- 이름 없는 매직 넘버, 근거를 적지 않은 `as` 단언과 `any`.
- 찾아서 지울 수 있는 것은 점수와 무관하게 발견 즉시 지운다.

## 도구 요구사항

- `typescript`는 5.x다. 이 도구는 TypeScript 5.x의 구문 트리 API를 쓴다. TypeScript 7은 쓰지 않는다.
