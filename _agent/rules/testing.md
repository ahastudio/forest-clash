# 테스트

## 도구와 위치

- 테스트는 Vitest로 쓴다.
  테스트 파일은 테스트하는 파일 옆에 `<이름>.test.ts`로 둔다.
- 테스트 도우미(가짜 캔버스, 가짜 오디오, 마주 선 두 캐릭터)는 `src/testing/`에 둔다.
  이 폴더는 게임에 들어가지 않고 커버리지에서 빠진다.
- 계산 시간을 재는 벤치마크(`*.bench.ts`)도 `src/testing/`에 둔다. 테스트와 달리 시간을 재는 것이 목적이므로 `pnpm run bench`로만 실행하고, 기준은 `pnpm run budget`이 판정한다.
- 실행은 `pnpm test`(빠른 확인), `pnpm run coverage`(커버리지 검사), `pnpm run check`(코드 검사), `pnpm run check:full`(성능·보안·빌드까지 전체 점검)이다.

## 커버리지 100퍼센트

- 문장·분기·함수·줄이 모두 100퍼센트여야 한다(`vite.config.ts`의 `coverage.thresholds`).
  줄만 100퍼센트이고 분기가 남은 상태는 통과가 아니다. 네 항목의 임계값이 모두 100으로 적혀 있어야 한다.
  기준을 낮추거나 파일을 커버리지에서 빼서 통과시키지 않는다.
- 줄만 지나가게 하는 테스트를 쓰지 않는다.
  모든 테스트는 결과(상태, 사건, 그려진 글자, 낸 소리)를 `expect`로 확인한다.
- 테스트하기 어려운 코드는 테스트를 억지로 끼우지 않고 코드를 나눈다.
  도달할 수 없는 분기는 테스트로 채우지 않고 코드에서 없앤다.

## 무엇을 어떻게 테스트하나

- 엔진: 기능 문서(`specs/`)의 규칙을 마주 선 두 캐릭터로 재현해 확인한다(`scenarios.test.ts`).
  프레임 표의 수치(발동, 막힘·맞음 이득)는 실제로 재서 표와 비교한다.
  한 모듈의 가지는 상태를 직접 만들어 확인한다.
- 컴퓨터 상대: `Math.random`을 정해 둔 값으로 바꿔(`rolls`) 판단이 갈라지는 자리마다 확인한다.
- 화면: 그린 것을 기록만 하는 가짜 캔버스(`fakeCanvas`)로 호출과 글자를 확인한다.
- 소리: 가짜 오디오 장치(`FakeContext`)로 어떤 소리가 어떤 시각에 이어졌는지 확인한다.
- 회귀: 컴퓨터끼리 한 판을 끝까지 두고 모든 프레임의 상태를 하나의 값으로 요약해 기대값과 비교한다(`src/regression.test.ts`).

## 결정성과 속도

- 테스트는 언제나 같은 결과가 나와야 한다.
  무작위(`Math.random`)와 시각(`Date.now`)은 고정하거나 인자로 받는다.
- 테스트는 전체가 몇 초 안에 끝나야 한다.
  긴 시뮬레이션은 필요한 만큼만 돌리고, 같은 확인을 여러 테스트에서 되풀이하지 않는다.
- 테스트끼리 상태를 공유하지 않는다.
  전역을 바꿨으면 같은 테스트 안에서 되돌린다(`afterEach`).

## 기대값을 바꿀 때

- 테스트가 실패하면 코드의 결함인지 테스트가 낡았는지를 먼저 가른다.
- 회귀 테스트의 기대값(`toMatchInlineSnapshot`)은 동작이 바뀐 이유를 설명할 수 있을 때만 `-u`로 갱신한다.
